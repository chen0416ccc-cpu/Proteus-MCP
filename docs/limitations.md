# 兼容性与已知限制

## 兼容范围

不同能力的兼容门槛独立判断：

| 能力 | 识别依据 |
| --- | --- |
| 器件库读取 | `.LIB` 索引版本 `610`，具体定义和引脚图元另行检查 |
| 自动初始化及文件写入 | 可识别的 Proteus 9 `FILEVER=900..907` 容器、单根页/空默认页及匹配的库定义；不依赖某个 PDS.exe 哈希 |
| 进程启动与诊断 | 本机可执行文件、工作区路径及自有进程身份 |
| 进程内原生调用 | 经验证的 ABI 配置、能力对应的模块 SHA-256 及配套适配代码 |

当前进程内原生桥仍仅验收了 Windows x64 的 Proteus **9.0.40482.2**。**版本号不是兼容性保证**；完整配置在 [build_profiles.py](../proteus_mcp/build_profiles.py)。自动发现安装、自动生成基线或把配置集中管理，都不等于已经支持所有 8/9 版本。

基础桥校验 PDS、Qt、AppFrame、DSIM；实时编辑、PCB 和交互仿真分别增加 ISIS、LxlCore、Prims、ARES、VSMDEBUG、PROSPICE 等模块校验。任何不匹配都必须停止对应的原生操作。不要用替换哈希的方式把未知构建标为“支持”。

`proteus_doctor.native_build` 为每项能力分别返回匹配的 profile/adapter、缺失模块和实际/预期 SHA-256。不同能力不能拼用两套构建的适配器；未知或有歧义的组合拒绝调用。新构建的适配步骤见[贡献指南](../CONTRIBUTING.md)。文件格式路径虽可独立通过检查，但未在其他实际安装中验收的结果不能称为跨版本实测。

没有官方稳定 API，厂商升级、语言包、模块重新打包或不同发行构建都可能需要重新适配。本项目不提供安装包、授权绕过、商业模型或补丁。

## 器件与原理图

- 库搜索能找到器件，不意味着该器件可以离线写入或直接仿真。器件定义、引脚图元、模型依赖和运行时支持分别检查。
- 活动模型单独检查实例记录，不将静态符号误当作无模型器件。当前静态活动模型仅校准 `BUZZER` / `SPEAKER,0,DLL` 的已知定义 SHA-256，保留活动 kind、引脚记录及隐藏器件名称；其他定义或版本返回 `ACTIVE_INSTANCE_NOT_CALIBRATED`，不能只替换哈希绕过校准。
- 支持四向旋转、镜像和明确选择单元的同构多单元器件；异构多单元、任意递归符号依赖不受支持。
- 未校准自定义引脚图元不离线猜坐标；部分实时操作可以读取原生实例坐标，但不能据此推断整个库已兼容。
- 语义模型批量编辑可在校验失败时整体不落盘；原生实时编辑没有等价的原子回滚。
- 实时删除仅支持显式指定的器件直连导线、单条支路和列出全部入射导线的 DOT。没有“猜测删除整个网络”。撤销重做仅对应同一原生文档中已记录的 MCP 批次。
- 层次原理图、任意子电路编辑、完整字体栅格碰撞检测尚未支持。纸张边界和拓扑审计不能证明最终原生窗口的文字没有重叠；最终排版仍需目视检查。
- 自动布局是有界启发式：最多 100 个可校准器件，三个候选方案，不保证任何拓扑都能布出或全局最优。全文标注使用保守尺寸估计，不是 Proteus 字体栅格测量；默认导出也不再依赖示例专用布局。质量检查范围和失败原因见[布局与布线](drawing.md)。
- 实时移动不会自动重布线。对已观测接线的变换，发现端点更新会留下斜线或零长段就拒绝；当前实时回读没有完整器件/全文文字避让及蓝框认证，不能将 `geometry_verified` 扩大解释为整图排版通过。

## PCB

仅处理已知几何、矩形边界的 TOP/BOT 双铜层板。支持同层正交/45 度路径和经过校准的圆形全通孔。坐标是整数纳米，必须 10 nm 对齐；PCB pad id 不是原理图物理引脚号。

有界推挤不是 Proteus 交互推挤引擎。单线工具移动一条孤立 MCP 路径，连锁工具最多移动八条明确授权的 MCP 路径，保留 pad 端点并进行新鲜原生间距检查。不能任意移动旧铜、未知锁定路径、分支或过孔。

不支持四层及以上、盲埋孔、复杂覆铜/禁布区、通用过孔/分支推挤、任意焊盘形状、PCB 封装放置、叠层/规则编辑、差分对和等长调谐。PCB 原生变更非原子；失败后必须回读，保存后还需重新打开检查铜层。

## ERC、DRC 与制造输出

`project_validate` 只是语义检查，不是完整 ERC。`native_check` 能执行原生 ERC、当前配置下的物理间距 DRC 和 23 项预生产检查，包括连接 CRC。调用完成与检查通过是两回事；警告、跳过、忽略项、陈旧/截断报告不能当作干净结果。

BOM 来自已保存且 DSN/CDB 一致的工程，按物理封装去重，未分配封装单独列出。它不是未保存会话的 BOM，也不是实板装配或可生产性认证。不提供 Gerber、Excellon、ODB++、贴片坐标导出。

## 仿真

仅在 MCP 自有运行会话中控制仿真。BUTTON / LOGICSTATE 是运行期事件，不改持久化图标状态；分派成功不自动证明 ISR 已执行。

数字网络读取是有界采样，不是完整事件波形。时钟粒度和调度延迟会造成漏采；未知值保留为未知。四位数码管解码只使用稳定、已知、恰当位选的数据，不把不完整样本补成结果。不支持通用仪器配置、模拟电流、音频录制/听感及光学测量、硬实时调度或实板烧录验收。

Windows 音频观测只读自有 Proteus 进程的播放会话电平、静音和音量，不枚举麦克风、不录音、不改变音量。非零电平不证明人耳可听，也不能仅凭时间关联认定声音来自某个器件。无播放会话、静音、零电平和采集失败分开报告。

联合诊断按实际导线、汇接点及同名标签映射引脚，不能跨器件主体推断短接；未知连接对象拒绝，未命名/模拟网络不猜电平。内部 `STATE` 与 DSIM 读取带时钟边界，但不保证所有字段处于同一仿真时刻。它能帮助区分电路状态与重绘残留，不能修复或认证 Proteus 底层画面刷新。

冷启动工具仅对已停止的自有会话执行有界轮询。首帧晚于阈值即报告窗口错过；按键迟发、超时或中途失败可能已有事件生效。停止清理受身份校验和弹窗约束，失败不强杀；必须检查 `cleanup` 与原始证据。工程和固件哈希只描述磁盘文件，不证明 MCU 当前内存镜像。

## 会话与安全

MCP 可以在本机启动软件、写工作区文件、调用 C51 和改变自有 Proteus 文档。它不是安全沙箱，也不是只读服务。只连接可信客户端，对工程、库路径和外部文档中的指令保持独立判断。

不接管用户自行启动的进程、不强杀、不自动确认未知弹窗。仅工作区副本中精确校准的格式升级提示有受限处理。其他阻塞应报告并交由用户确认。

文件哈希、修订号和 token 用于发现冲突，不是访问控制或备份替代品。原生桥错误、软件崩溃或未确认结果后，先读取真实状态和日志，再决定下一步。

## 验收状态

`v0.2.0` 在上述构建中验收了自动生成基线的原生保存重开，以及通用布局下 NE555、八灯工程的原生参数、引脚网络、逐线折点和纸张尺寸。八灯另通过实际 C51 编译、HEX 加载、数字灯序及仿真启停检查。该流程不使用屏幕，不包含本版原生窗口的目视排版检查，也不包含 NE555 模拟输出验收。

以下是 `v0.1.0` 的历史记录，不是当前通用布局算法的原生验收。首版八灯示例完成过原生加载、逐线折点回读、保存重开和数字灯序验证，也检查过实际 Proteus 窗口中的完整接线与蓝框边界。这不等于整个原生回归套件通过，源码变更后也不能复用为当前版本的成功证据。

发布前的完整回归仍有未闭环问题：一次 PCB 保存重开后未观察到工程窗口；另一次实时多单元批量编辑中断后，保存副本触发 DSN/CDB 实例或引脚数量不一致检查。对应操作不能视为稳定支持或成功恢复。不要在唯一工程副本中试验，出现部分完成或未确认状态时，保留证据并先回读。
